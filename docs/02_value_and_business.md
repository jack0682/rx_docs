# 02. 제품의 목적·기여·사업 가치

현재 작업 단계: **설계 문서 작성·구체화**. 실제 코드·빌드 기반·저장소 구축은 설계 정리 후 후속 지시에 따라 진행한다. 진행 순서는 [설계 로드맵](/Users/ojaehong/RX_automation/rx_ws/docs/00_design_roadmap.md)을 따른다.

[전체 문서 안내](/Users/ojaehong/RX_automation/rx_ws/README.md) · 고객 효과와 제품 투자에 대한 제안

## 1. 제품의 목적

RX의 고객 목적은 **필요한 생산을 더 적은 반복 작업과 예측 가능한 운영 부담으로 수행하게 하는 것**이다. 첫 현장의 주된 도입 이유는 인건비 절감으로 확인됐다. 절감액·구매 의사·수익성은 아직 측정되거나 계약으로 확정되지 않았다.

회사 목적은 현장별 자동화를 구축하면서, 연결·실행·진단·배포에 필요한 소프트웨어를 반복 사용할 수 있게 하는 것이다. 같은 품질을 더 적은 설치·수정·지원 공수로 제공할 수 있어야 제품 투자의 효과가 생긴다.

## 2. 누구에게 무엇을 기여하는가

아래 역할은 제품 사용과 구매 구조를 설계하기 위한 분류다. 실제 첫 현장의 담당자와 의사결정 권한은 확인해야 한다.

| 대상 | 개선할 일 | RX가 제공할 능력 | 검증할 효과 |
|---|---|---|---|
| 작업자 | 반복 공급, 상태 확인, 이상 때의 판단 | 작업 선택·상태·개입 안내·복구 절차 | 직접 작업·대기·개입 시간 |
| 생산 관리자 | 무엇이 진행·중단됐는지 파악 | 작업지시·실적·정지 이유의 연결 | 공급 지연·운영 손실과 계획 대비 실적 |
| 생산기술·통합 엔지니어 | 현장 구성과 변경 적용 | 프로파일·공정 패키지·시험·배포 | 설치·변경·재검증 공수 |
| 유지보수 담당자 | 원인 조사와 생산 복귀 | 버전·상태·원본 오류·개입 이력 | 진단·복구 시간과 현장 방문 |
| 고객의 구매 결정자 | 투자 효과와 지원 범위 판단 | 비교 가능한 인수·운영 지표와 비용 범위 | 현금 비용·운영 배치·총비용의 변화 |
| RX 회사 | 납품 확대와 지원 비용 관리 | 공통 릴리스·재사용 모듈·검증 자산 | 납품 기여이익·반복 적용 공수 |

자사 로봇을 사용하는 현장에서는 소프트웨어·하드웨어를 함께 개선할 수 있다. 타사 로봇을 사용하는 현장에서도 RX의 구축·운영 기능이 가치를 제공해야 한다. 로봇 제조사 수가 늘었다는 사실만으로 고객 가치가 발생했다고 판단하지 않는다.

## 3. 인건비 절감을 어떻게 판단하는가

같은 품목·생산량·품질 조건에서 자동화 전후의 작업자 총투입을 비교한다. 초기 준비, 소재 보충, 감시, 검사, 이상 확인, 복구, 추가 정비를 포함한다. 한 사람이 동시에 수행하는 업무의 시간을 중복 계산하지 않는다.

**작업 시간 감소 = 비교 가능한 기존 작업자 투입 시간 − 자동화 후 남은 작업자 투입 시간.**

이 감소가 실제 유급 근로시간·초과근무·외주비 감소로 이어지면 현금 절감으로 검토한다. 다른 업무에 재배치되는 시간은 생산 여력 또는 배치 개선으로 구분한다. 추가 채용 회피는 해당 채용 필요와 비교 기간이 확인돼야 한다.

제공된 레이저 가공 시간은 CVR_F FRONT/REAR 각 8분, ECC_SHAFT 6분 30초, FLANGE_R 5분, FLANGE_L 2분 30초다. 이는 작업자 노동 시간이나 전체 사이클이 아니다. 기준 수량과 품목 비중도 미확인이므로 절감 인원·평균 생산량·투자 회수 기간을 산출하지 않는다. [현장 설명의 출처](/Users/ojaehong/research_RX/RX_machine_tending_business_baseline_v0.2.md)

## 4. 제품 기여를 측정할 지표

다음은 지표 정의 제안이다. 수치 목표와 측정 기간은 파일럿 전에 합의한다. 고객 합격 판정이 없는 경우 ‘양품’을 임의로 정의하지 않고, 현재 확인 가능한 공정 완료 수량과 구분한다.

| 지표 | 정의와 필요한 자료 | 해석의 한계 |
|---|---|---|
| 작업자 투입 | 역할별 실제 투입 시간 / 같은 조건의 처리 수량 | 감시·개입·정비 누락 금지 |
| 개입 빈도 | 사람이 확인·조치한 사건 수 / 시도한 사이클 수 | 정기 보충과 비정상 복구를 분리 |
| 자동 완료 비율 | 합의한 자동 범위에서 개입 없이 완료한 사이클 / 전체 시도 | 거부·중단·불명도 분모와 사유에 남김 |
| 복구 시간 | 이상 감지부터 정의된 생산 재개까지의 시간 | 원인·대기·작업 유형별 분포로 확인 |
| 공급 대기 | 설비가 다음 소재 공급 때문에 대기한 시간 | 순수 가공·정비·품질 대기와 구별 |
| 결과 불명 | 결론을 확정하지 못한 작업의 수·지속시간·해결 근거 | 불명을 숨겨 수치를 개선하지 않음 |
| 재현 가능한 납품 | 재설치·복원 시험을 통과한 납품 조합 | 문서 존재만으로 통과 처리하지 않음 |
| 반복 적용 비용 | 두 번째 장비·현장의 개발·설정·시험·지원 공수 | 난도·설비 개조 차이를 함께 기록 |

신뢰성을 하나의 성공률로 축소하지 않는다. 작업 성공, 관측 정확성, 이상 감지, 제어권, 복구 가능성은 함께 평가해야 한다.

완료 근거가 부족한 장비를 채택할 때는 자동 범위를 축소할지, 명시적인 작업자 확인을 둘지, 센서·장비 논리를 보완할지 결정한다. 그 결과로 생기는 노동 투입·개조·재검증·지원 비용을 효과 비교와 납품 원가에 반영한다. 필수 근거의 부족을 화면 경고만으로 해소했다고 취급하지 않는다.

## 5. RX의 비용과 수익

첫 상품의 검토 단위는 ‘한정된 현장 자동화 구축 + 소프트웨어 사용·지원 범위’다. 장비 비용, 지그·그리퍼, 설비 개조, 현장 개발, 시운전·교육, 보증·지원의 직접비를 납품별로 기록한다. 공통 제품 개발·검증·영업 비용은 별도 추적한다.

**납품·지원 기여이익 = 해당 매출 − 장비·제작·현장 구축·계약 지원 직접비.** 이 값은 회사 전체 영업이익이 아니다. 공통 개발비·영업비·운영비를 감당할 반복 납품 규모도 함께 검토해야 한다.

| 상업적 구분 | 문서로 정할 것 |
|---|---|
| 기본 납품 | 지원 품목·장비·공정·기능·인수 조건·교육 |
| 변경 작업 | 새 품목·지그·로봇·설비 개조와 필요한 재검증 |
| 유지보수 | 대응 시간·대상 버전·원격/현장 지원·부품 범위 |
| 플랫폼 개발 | 재사용 가능한 공통 개선의 투자·소유·배포 정책 |
| 라이선스 | 소프트웨어·제조사 SDK·OS·상용 컴포넌트의 사용·배포 조건 |

금액·마진·응답 시간·구독 요금은 이 문서에서 가정해 확정하지 않는다. 계약 단계에서 실제 원가와 지원 조직의 역량을 기준으로 정한다.

## 6. 아키텍처 선택이 사업에 기여하는 조건

| 선택 | 기대 기여 | 추가로 드는 비용 | 채택을 유지할 근거 |
|---|---|---|---|
| 공통 작업 계약 | 여러 장비의 상태·복구·앱을 재사용 | 계약 설계와 적합성 시험 | 두 번째 구현의 공통 코드 변경·결함 감소 |
| 어댑터·프로파일 분리 | SDK 변경과 현장 신호 변경을 나눠 처리 | 버전·설정 조합 관리 | 변경 영향과 시험 범위를 실제로 제한 |
| 기록·진단 묶음 | 지원 담당자가 상태를 재구성 | 저장·보존·진단 도구 운영 | 문의당 진단 공수와 재현 실패 감소 |
| 공통 릴리스 | 검증된 수정의 여러 현장 적용 | 호환성·회귀·업데이트 시험 | 개별 분기 유지 비용 감소 |
| OS 이식성 | 고객·SDK의 배포 선택 폭 | OS별 빌드·패키징·시험 | 실제 납품 수요와 검증 비용이 정당화 |

일회성 단순 셀에서는 PLC·로봇 프로그램과 전용 HMI만으로 충분할 수 있다. RX 프레임워크 투자는 장비·현장·공정이 반복 추가되고 공통 운영·유지보수 요구가 생기는 사업 전제에서 정당화한다. 반복 적용 효과가 작다면 초기 공통화 범위를 축소하는 것이 타당하다.
