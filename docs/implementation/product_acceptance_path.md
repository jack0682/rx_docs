# 제품 전체 흐름의 구현·인수 순서

2026-09-13. 사용자 지시에 따라 시간·토큰보다 제품의 완성도와 검증을 우선한다. 라이브러리·검증 파일의 개수를 전체 제품 완성도로 환산하지 않는다. 아래 순서는 R01–R30을 제거하거나 범위를 축소하는 새 목표가 아니라, 이미 구현한 하위 기능을 실제 납품 흐름으로 연결하는 우선순위다.

## 첫 통합 인수 흐름

**새 설치 → 두 이미지 기동 → 등록 단말의 앱 로그인 → 모의 셀 구성·독립 검토 → 수량2 작업 시작 → 실제 실행기 배정·두 소재 처리 → 중간 이상·개입·재개 → 구성 변경 → 백업·복원 → 명시적 새 시작.**

모든 단계가 같은 installation/package/Run/Case/Change 식별자로 추적되어야 한다. 개발 서버, 시험 전용 실행파일 또는 작업마다 수동으로 고친 실행기 설정을 제품 경로로 세지 않는다. 모의 검증과 물리 qualification을 구별하고 첫 실제 셀은 NOT_COMMISSIONED로 유지한다.

| 순서 | 연결할 제품 동작 | 합격 증거 | 현재 상태 |
|---|---|---|---|
| P01 | 검토된 설치 입력·두 이미지로 초기화/기동, HTTPS 앱 접속 | 고정 S bundle, P가 검증한 단말 인증서, 실제 로그인·한글 font·상태 화면, 개발 서버 없음 | UI 제공 구간 검증. phase73 실제 두 이미지·등록 단말 로그인/CreateRun 응답 회수; 전체 Host/실행기 composition은 후속 |
| P02 | 작업자가 승인 공정·수량을 선택하여 시작하고 S가 지속 배정받음 | StartRun 응답 유실/화면 새로고침/실행기 재접속에도 같은 Run·소재 시도, 두 소재 완료와 자원 인계 | 미완료. 기존 CreateRun UI와 per-Run 실행기 설정 사이를 연결해야 함 |
| P03 | 이상 확인·개입·복구·명시적 재개 | UNKNOWN 미해결·후발 모순·참여자 미종료·만료된 준비에서는 재개 거부, 정상 transient와 latched 철회 구별 | 미완료. ACK 이후 recovery/restart 계약·UI 연결 필요 |
| P04 | 승인된 설정 변경과 설치 교체·복원 | quiet/fence·Host 원장/설치 확인·정확한 교체 receipt·APPLIED_UNQUALIFIED·재검증/독립 승인·별도 시작 | 일부 구현. 현재 제안/검토/stage/읽기 비교/영속 준비까지, 실제 교체·P 조정은 미완료 |
| P05 | 자사 모델별 실제 제어·관측·수명 관리 | 제품 factory의 실제 provider, 원본 시각/세대·독점 소유·상태 관측, controller 교체/외부 목표/응답 유실/종료 반례 | 일부 구현. JTC production provider는 미연결, 자사 전체 지원 완료가 아님 |

P01/P02를 먼저 완결된 모의 운영 흐름으로 묶고 P03을 연결한다. P04/P05의 경계와 자료 형식은 이 과정에서 수용하되, 현재 승인·동작 사실이 없는 것을 true/READY 기본값으로 채우지 않는다.

## 연결 경계의 고정 원칙

- UI bundle의 소스·빌드·산출물은 S 소유다. P는 검증된 불변 바이트를 같은 terminal HTTPS origin에서 제공한다. 인증서 헤더 프록시로 단말 신원을 전달하지 않는다.
- static UI의 접근과 인간 로그인·현재 역할·셀 권한은 다른 판단이다. UI가 보였다고 작업이 허가되지 않는다. API의 오류/404를 SPA HTML로 바꾸지 않는다.
- Run 배정은 영속 ID와 현재 P 상태에 연결한다. 실행기 재시작을 새 작업이나 자동 재개로 해석하지 않는다.
- Host 종료·준비 기록과 native evidence는 다른 원장 의미다. 정지 당시의 snapshot이 현재 소재 지지나 새 제어권을 보증하지 않는다.
- 실제 controller generation은 bridge instance나 action 이름으로 대체하지 않는다. JTC 원본 관측 시각을 조회 시각으로 새로 찍거나 시험용 true Authority를 제품에 등록하지 않는다.

## 병행해서 유지하는 전체 요구

위 흐름 외에도 R01–R30의 미완료 항목을 계속 관리한다. 고주기 stream, 공개 계약의 나머지 wire 경로, 외부 UI 패널, 계정·단말 관리, 관측/이력의 부하·보존, CPU/GPU/OS 지원 조합, 호스트 관리 도구, 백업/복원과 binary rollback, 납품·교육·인건비/지원 공수 측정은 [요구 추적표](requirements.md)에 남는다.

실물 신호·극성·갱신주기, 로봇/그리퍼·교정, 지지·정지·전원 상실 거동은 현장 근거가 필요하다. 이 입력을 가상으로 채워 제품 인수를 완료 처리하지 않는다. 구현 가능한 소프트웨어와 모의 실패 경로는 병행해서 계속 검증한다.

## 독립 검토

2026-09-13의 제품 흐름 감사는 실제 entrypoint, supervisor recipe, UI mutation, 실행기 설정, recovery/restart stub, Host factory를 읽어 위 연결 공백을 확인했다. 별도 JTC 감사는 observe_sources 부재와 controller generation/독점 제어·지원 상태의 실제 제공자 부재를 확인했다. 독립 maintenance 검토에서 발견한 전체 기동 설정 바꿔치기 반례는 StopSeal의 전체 Configuration digest 대조로 수정했다. 읽기 검토와 실행 시험은 별도 증거로 기록한다.
