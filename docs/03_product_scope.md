# 03. 제품 범위와 단계별 제공 수준

## 1. 솔루션의 범위

회사는 로봇 선정·배치, 지그·그리퍼 설계, 공정 설계와 장비 연동을 수행한다. 납품 범위에는 소프트웨어뿐 아니라 기구·전기·설비 작업, 설치·시운전·교육·지원이 포함될 수 있다. 실제 포함 항목은 현장 계약으로 고정한다.

| 영역 | 회사가 제공할 일 | 소프트웨어가 연결해야 할 정보 |
|---|---|---|
| 로봇·설비 선정 | 접근성·작업성·운영 조건에 맞는 조합 결정 | 장비 식별·지원 버전·능력·제한 |
| 지그·그리퍼 | 소재·고정·취급에 맞는 설계와 제작 | 설계 revision, tool·하중·교정·관측 조건 |
| 공정 설계 | 작업 순서·분기·병행·개입·복구 계획 | 버전 있는 공정 정의와 작업 계약 |
| 전기·제어 연동 | 명령·센서·제어권·보호 경계 구성 | IO 매핑·PLC 프로그램 버전·작업 의미 |
| 납품·지원 | 설치·시험·인수·교육·유지보수 | 배포 명세·검증 증거·운영·복구 안내 |

소프트웨어 제품 자체에 CAD나 모든 장비 제어기를 새로 구현할 필요는 없다. 대신 적용된 기구·전기·교정 revision과 실행 조건을 참조하고 변경 영향을 추적해야 한다.

## 2. 소프트웨어 제품의 범위

| 영역 | 첫 제품에서 제공할 최소 기능 | 확장 기능 |
|---|---|---|
| 구성·시운전 | 장비·프로파일 등록, 연결·신호 확인, 검증된 공정 선택 | 편집 편의, 템플릿·시뮬레이션, 변경 영향 검토 |
| 현장 운영 앱 | 준비 상태, 작업 시작·중단 요청, 진행·이상·개입·이력 | 여러 셀 보기, 역할별 상세 화면 |
| 공정 실행 | 한정된 순서·조건·분기와 중단·복구 흐름 | 여러 공정·자원·병행 작업 |
| 공통 Runtime | 식별·중복·상태·자원·기록·재시작 조정 | 규모·가용성 요구에 따른 확장 |
| 장비 연동 | 첫 로봇과 레이저 PLC의 검증된 작업 | OMY·UR·FR3 및 다른 CNC·주변장치 |
| 개발 도구 | 모듈 템플릿, 모의 장비, 계약 시험, 진단 도구 | 파트너 SDK와 호환성 검증 자동화 |
| 공정관리 | 품목·목표 수량·공정 버전이 있는 작업지시, 완료·보류 실적 | 대기열·셀 배정·정지 분석·외부 MES/ERP 연계 |
| 배포·유지보수 | 설치·자동 시작·백업·복원·진단 수집, 지원 조합 명시 | 관리된 업데이트와 다현장 지원 |

첫 제품의 공정 편집은 엔지니어가 관리하는 파일·폼으로 시작할 수 있다. 그래픽 편집기를 먼저 완성해야 실행 서비스를 만들 수 있는 구조로 잡지 않는다. 고객 작업자는 검증된 공정을 선택·운영하는 흐름부터 제공한다.

## 3. 시연·제품·확장을 구분한다

| 단계 | 약속할 수 있는 범위 | 다음 단계에 필요한 증거 |
|---|---|---|
| 첫 셀 시연 | 합의한 초기 조건·작업·개입 범위에서 실제 동작 수행 | 반복 동작·관측·중단과 남은 결함 기록 |
| 운영 파일럿 | 정한 품목·장비·조건에서 실제 작업자와 반복 운전 | 개입·복구·신뢰성·노동 투입 측정 |
| 첫 납품 제품 | 검증한 조합의 설치·운영·지원·인수 범위 | 설치 재현·교육·복구·지원 준비와 인수 |
| 반복 납품 제품 | 다른 장비·현장에 공통 제품과 패키지로 적용 | 재사용 범위·변경 공수·회귀 시험 결과 |
| 장기 플랫폼 | 더 많은 장비·공정·관리 기능과 파트너 확장 | 실제 수요·추가 계약·지원 역량 검증 |

시연 한 번의 성공을 반복 무인 생산, 모든 장비 호환, 기능 안전 인증이나 품질 합격으로 확대하지 않는다. 후속 단계를 위해 시연을 지나치게 키우지도 않는다. 각 단계에 필요한 가장 작은 경로를 먼저 완성한다.

## 4. 첫 레이저 셀의 범위

설비 PLC는 Q03UDVCPU와 CC-Link 구성으로 확인됐다. 로봇 후보는 OMY·UR5e·FR3이며 첫 투입 장비는 선택해야 한다. 첫 시연은 지그가 있는 레이저 설비의 소재 공급이다. [레이저 PLC 근거](/Users/ojaehong/RX_automation/rx_ws/references/laser_plc_interface.md)

| 동작·기능 | 현재 범위 | 결정해야 할 경계 |
|---|---|---|
| 소재 집기·투입 | 첫 작업 후보 | 그리퍼·소재 보유·투입 완료 근거 |
| 척 닫기 | 언급된 작업 | 담당 제어기·고정 판정·열기 담당 |
| 문 닫기 | 언급된 작업 | 닫힘·잠금·가공 허가의 구분 |
| ‘빼기’ | 의미 미확정 | 로봇 후퇴인지 소재 회수인지 |
| 다음 소재 준비 | 언급된 작업 | 병행 가능 조건과 공유 자원 |
| 가공 시작·완료 | 연동 정의 필요 | RX·PLC·레이저 제어부의 담당 |
| 이상·복구 | 필요한 기능 | 자동 처리·작업자 개입·복귀 기준 |

이 표는 실제 실행 순서가 아니다. 순서와 종료 상태를 장비·공정 담당자가 확인하기 전에는 운전 절차로 사용하지 않는다.

## 5. 장비 지원과 호환성의 범위

지원 선언은 **기계 모델 + 제어기·firmware + SDK/ROS + OS·CPU + 어댑터 + 프로파일 + 작업 범위 + 검증 결과**의 조합으로 관리한다. CPU나 제조사의 이름만 등록된 상태는 ‘연동 후보’로 분류한다.

| 대상 | 이번 기준의 위치 |
|---|---|
| Q03UDVCPU 기반 레이저 PLC | 첫 현장의 직접 연동 대상. 실제 설정·신호·PLC 논리 검증 필요 |
| 자사 open_manipulator·OMY, AI Worker, AI Sapiens | 필수 기본 소프트웨어 지원 대상. 관련 의존성과 모델 registry를 solutions에 포함하고 제품군별 검증 필요 |
| UR5e·FR3 등 타사 로봇 | 추가 연동 후보. 선정 장비별 구현·실물 검증 |
| FANUC CNC/PMC | 회사 장비 분포를 고려한 확장 우선 후보 |
| MCT-2 Siemens | 현장 제어반 확인 자료 있음. 정확한 NCU·옵션 미확정 |
| 모바일 매니퓰레이터·휴머노이드 | 자사 제품의 연결·설정·진단·해당 제어 기능은 기본 통합 범위. 새로운 현장 공정·이동·도킹 조합의 자동화는 추가 설계·검증 |
| 외부 미니컴퓨터 | 메인 PC에 연결되는 PLC형 부속 장치. 원격 RX 실행 호스트 요구로 해석하지 않음 |

## 6. 처음부터 제품에 넣지 않을 범위

첫 제품은 자체 Linux 배포판, 모든 로봇 운동 제어기의 재작성, 범용 CAD, 전사 ERP/MES 전체, 클라우드 상시 연결, 무인 자동복구 전 범위, 자사 필수 지원 범위를 넘어선 모든 OS·타사 장비의 동시 지원을 요구하지 않는다. 자사 지정 패키지와 필요한 의존성의 기본 지원은 유지한다. 추가 기능은 실제 고객 요구와 기존 제품 활용 가능성, 검증·유지 비용으로 판단한다.

운영 중 인명·설비를 보호하는 기능은 설비 위험성 평가에 따라 적합한 장치·회로·제어에 배정한다. 일반 RX 소프트웨어의 실행 허가나 통신 heartbeat만으로 그 보호 기능을 대체한다고 선언하지 않는다.

## 7. 범위 변경 규칙

새 기능은 해결할 현장 문제, 지원 대상, 책임, 완료·이상 의미, 배포·검증 영향, 유지보수 비용을 함께 제안한다. 단일 현장의 특수 요구는 먼저 그 현장 패키지에 두고, 다른 구현에서도 반복되는 의미가 확인되면 공통 제품으로 승격한다.
