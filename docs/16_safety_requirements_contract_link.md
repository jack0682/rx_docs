# 안전·위험성평가 자료와 RX 계약의 연결

> 후속 확정 결과: [셀 운영 계약 v1.0](18_cell_operations_contract.md). 이 문서는 그 설계를 위한 선행 입력/분석으로 보존한다.

2026-09-10 · 상태: 참고 대화 반영 및 후속 설계 입력. 안전기능 상세 명세·적용 표준 채택·인증 판정은 아직 완료하지 않았다.

## 1. 참고한 자료와 결론

[인증 문서 분석 및 정리](codex://threads/01a07eaf-57d0-73b1-9acb-124c24f33040)의 요청·결론과 연결된 문서를 검토했다. 핵심 입력은 [머신텐딩 위험성평가 심화 정리](</Users/ojaehong/research_RX/output/documents/machine_tending_risk/머신텐딩_위험성평가_심화_정리.md>), [4종 자료 통합 분석](</Users/ojaehong/research_RX/humanoid_safety_documents_integrated_analysis_2026-09-08.md>), [안전 가이드 분석](</Users/ojaehong/research_RX/humanoid_safety_guide_analysis_2026-09-08.md>)이다. 가이드의 정지·리셋·안정성 관련 원문 발췌와 공식 표준의 공개 범위도 대조했다.

RX는 **작업이 어떤 결과에 도달했는지 기록하는 계약에, 그 작업을 어떤 사용 조건과 안전기능 아래 허용하는지에 대한 근거를 연결해야 한다.** 기존 v1.0은 실행 신뢰성·제어권·불명 결과의 처리 기준이다. 여기서 추가할 것은 현장 위험성평가와 안전기능의 책임·제약·검증자료를 연결하는 설계다.

공장 내 로봇 응용·셀의 통합·운영·정비는 ISO 10218-2의 공개 범위에 포함되며, 이동 플랫폼의 이동 위험과 재료 가공 자체의 위험은 별도로 검토해야 한다. 따라서 첫 레이저 열처리기의 방사·열·문·척과 로봇의 결합 위험을 CNC 예제만으로 닫을 수 없다. [ISO 10218-2:2025](https://www.iso.org/standard/73934.html)

## 2. 참고 자료의 적용 경계

- 안전 가이드 v4는 초안, 위원회 문서는 추진계획, 전문가 의견서는 작성 예시가 있는 양식이다. 최종 채택·기관 승인·제품 인증의 증거로 사용하지 않는다.
- 대화에서 HTEC 별도 원문과 최종 검토 결과는 확보되지 않은 것으로 기록됐다. 미팅 목적과 준비 범위는 참고하되 기관이 특정 설계를 승인했다고 해석하지 않는다.
- 고정식·바퀴형·족형 세 구성을 모두 고려한다는 요청을 유지한다. 자료의 OMY·AIW 중심 미팅 준비 범위로 RX의 AI Sapiens 등 자사 필수 지원 의무를 줄이지 않는다.
- 해당 대화의 회사 가용 장비 정리 요청은 중단된 작업이다. 조사 중 검색 결과를 완성된 보유·가동 장비대장으로 취급하지 않는다.
- 기존 위험성평가 문서의 대표 사례는 CNC 선반/머시닝센터다. RX 첫 현장의 레이저 열처리 공정과 기계 고유 위험을 구분해 사용한다.
- 점검표의 500 mm는 해당 문서가 명시한 점검 항목이다. 가이드의 통신 두절 20초 등은 예시다. 어느 것도 RX 모든 모델의 공통 거리·timeout으로 옮기지 않는다. 상세 맥락과 오류는 통합 분석 노트를 따른다.

## 3. 기존 계약과의 대응

| 안전 자료의 논점 | v1.0에 있는 대응 | 추가로 구체화할 것 |
|---|---|---|
| 재설정·모드 선택·기동 구별 | 자동 restart 금지, mode와 실제 자세 구별 | reset 후 기동 허용 조건과 별도 시작 의도, safety reset과 일반 오류 acknowledge 구분 |
| 단일 제어점·권한 인계 | grant/fence, executor session, resource 인계 | 실제 pendant/현장/원격 owner의 표시와 외부 제어권 전환 검증 |
| 통신 이상과 현장 반응 | lease/deadman, 현지 보호 반응, 불명 결과 | 위험별 반응 시간·정지 대상·출력 유지·실제 안전기능의 할당과 검증 |
| 정지 중·정지 후 안정성 | torque-off 일괄 적용 금지, 소재/중력 지지 조건 | 모델·하중·자세·에너지별 정지 및 지지 기능의 명세와 시험자료 |
| 척·그리퍼 소재 인계 | 관측과 명령 bit 구별, 후조건·resource release | 실제 착좌·고정·유지의 근거, 압력/전원 상실 시 위험 감소 방법 |
| 설치와 제품의 공동 검증 | model/profile/calibration/release 고정 | 위험 ID→안전기능 ID→공급사/설치팀 구현→시험→잔존 위험의 추적 |
| 변경 후 재점검 | 불변 artifact/digest, profile별 admission | 공구·지그·소재·배치·정책·지도 변경이 어떤 평가/시험의 유효성을 잃게 하는지 |
| 도킹·뮤팅·안전 설정 변경 | 일반 mode/권한 틀은 있음 | 뮤팅의 적용성·감독 주체·진입/종료/고장 조건. 일반 config flag로 안전기능 해제 금지 |
| 운영자 개입·비상대응 | 역할과 human attestation | 개입 위치/이유·현장 점검·인수인계·적용 절차별 담당자 조건 |

특히 v1.0의 **MODE_TRANSITION 부작용 표시만으로 별도 기동 요구가 충족되지는 않는다.** 동작을 시작하는 native ‘모드 변경’ API는 실제로 무엇을 시작하는지 구분해 명세하고, 단순 운전모드 선택과 분리 가능한지 확인해야 한다. 조건을 충족하지 못한 binding은 생산 허용을 보류한다. 가이드 초안 본문 p.24, 29–30의 기동/모드 논점을 후속 계약 검토에 반영한다.

## 4. 세 책임을 구별한다

| 책임 | RX에서 설계할 내용 | 완료 근거 |
|---|---|---|
| 공정 실행의 신뢰성 | 중복·유실·결과·기록·자원 인계 | 계약 시험, 장애 주입, 장비 결과 상관관계 |
| 현장의 안전 관련 제어 | 감지→판단→통신/출력→구동 반응의 전체 기능, 고장 대응 | 기능별 요구와 구현 구조, 계산·분석·시험, 적용 조건 |
| 설치·운영의 적합성 관리 | 실제 기계 한계, 위험성평가, 변경 영향, 점검·인계 | 현장 구성과 연결된 검토·검증·운영 기록 |

platform은 평가·profile·근거를 관리하고 추가적인 작업 허용 조건을 적용한다. 위험 감소에 필요한 기능의 실제 실행 경로는 센서·안전 관련 제어부·로봇/장비 제어기 등으로 할당하고 검증해야 한다. Host·ROS·일반 gRPC·DB가 그 경로의 일부로 사용된다면 그 부분 역시 필요한 성능·고장 가정·검증 범위에 포함된다. ‘장비 측’이라는 배치만으로 기능안전이 달성되지는 않는다.

ISO 13849-1은 소프트웨어를 포함한 안전 관련 제어부의 설계·통합 방법을 다룬다. v1.0의 `quality=GOOD`, SHA-256, 불변식 검토를 PL/SIL 달성 근거로 바꾸지 않는다. 형식 검증 문맥의 safety property와 기계의 안전기능 성능은 용어가 같아도 검증 대상이 다르다. [ISO 13849-1:2023](https://www.iso.org/standard/73481.html)

## 5. 다음에 설계할 자료 묶음

다음 이름은 **설계 대상으로 제안한 개념**이다. 확정된 protobuf message나 새 field 번호가 아니다. 각 자료는 ID·revision·대상 구성·근거 출처·검토 상태·담당 역할을 갖도록 설계한다.

| 설계 대상 | 담을 내용 | 연결 경계 |
|---|---|---|
| 기계 사용 한계 | 로봇·tool·지그·소재·하중·자세·영역·바닥·에너지·모드·허용 동시동작 | C06, SiteConfiguration/BindingProfile |
| 위험성평가 참조 | 위험 ID, 작업/모드, 노출자·사고 경로, 감소조치, 잔존 위험, 적용 판본 | C06·C07 |
| 안전기능 명세 | trigger, 제어 대상, 필요한 상태/유지 시간, 반응 시간, 고장 대응, reset/start, 요구 성능 및 근거 | C05·C08 |
| 공급사 기능 증빙 | 기능 ID·검증 범위·펌웨어/설정·신호 의미·진단·제약·시험자료 | C06·C08 |
| 현재 상태 보고 | 어떤 기능/범위의 상태인지, 출처·세대·신선도·고장/뮤팅 상태 | C04·C05 |
| 변경 영향과 인수 기록 | 무엇이 바뀌어 어떤 평가·시험·허용 상태를 재검토해야 하는지, 실제 인수 범위 | C01·C06·C07 |

현재 상태 보고는 안전 관련 신호의 **표시·기록용 사본인지 실제 기능 경로의 신호인지**를 구별해야 한다. 승인된 평가서가 있다는 사실과 지금 interlock이 유효하다는 사실도 서로 대체하지 않는다. 사람의 확인 기록은 센서 진단·정지 성능을 대신하지 않는다.

새 schema가 필요한 항목은 영향 사례와 호환/migration을 정해 후속 revision에서 설계한다. v1.0의 기존 기록과 schema hash를 이 참고 반영 때문에 소급 변경하지 않는다.

## 6. 먼저 다룰 세 가지 사례

**SR01 — 부분 사이클에서 작업자 개입 후 재시작.** 척·그리퍼·소재·로봇 위치가 어디까지 확인됐는지, 누가 어느 구역에 개입하는지부터 정의한다. 오류 확인, 안전기능 reset, 실제 상태 재확인, 새로운 시작 의도를 별도 사건으로 검토한다. 연결 복구나 reset만으로 기존 대기 명령을 실행시키지 않는지 trace를 만든다. 예기치 않은 기동은 전기뿐 아니라 유공압·중력·저장 에너지까지 검토하는 범위다. [ISO 14118:2017](https://www.iso.org/standard/66460.html)

**SR02 — 소재를 잡고 설비 안에 있는 상태의 통신/에너지 상실.** 첫 레이저 셀에서 로봇·척·문·가공부 각각 어떤 위험동작을 제한하고 무엇을 유지해야 하는지 합의한다. 고정식은 축/소재 유지, 바퀴형은 차체 위치/제동, 능동 균형형은 전신 지지/정지 중 움직임을 추가한다. 특정 로봇의 정지 명령·시간값은 공급사 근거와 실제 시험 전 확정하지 않는다. 능동 균형 로봇 관련 ISO 25785-1은 공개 카탈로그상 CD 단계이므로 발행 표준과 구별한다. [ISO/CD 25785-1](https://www.iso.org/standard/91469.html)

**SR03 — tool/지그/소재/정책을 바꾼 뒤 이전 허용 상태 사용.** 새 구성 hash를 기록하는 데서 끝내지 않고, 영향을 받는 위험 행·안전기능·시험 범위를 찾아 재검토 상태로 전환하는 규칙을 설계한다. 데이터팩토리 점검표의 작업 변경 후 재점검과 담당자 조건은 해당 절차를 적용하는 현장 범위에 연결한다. 모든 납품 현장의 일률적인 교대 주기나 상주 인원 수를 임의로 만들지 않는다.

## 7. 작업 순서와 종료 조건

1. 첫 레이저 셀의 정상 작업과 작업자 개입 경계를 한 장으로 정리한다. 미확인 부분은 그대로 표시한다.
2. SR01–03에서 사람에게 상해가 생기는 경로를 나누고, 기계 한계와 위험 행을 작성한다.
3. 필요한 안전기능을 센서·판단·출력·구동까지 할당한다. 제작팀은 제품 한계/기능 자료를, OEM은 장비 연결 조건을, 설치팀은 결합 위험·검증을 정리한다.
4. 그 결과로 필요한 RX 상태·허가·기록·UI·binding을 정한다. 이미 있는 v1.0 의미로 충분한 것과 schema 변경이 필요한 것을 구별한다.
5. 위험→요구→구현 책임→검증 조건→결과→잔존 위험의 추적표를 남긴다.

이 후속 설계의 완료 기준은 첫 사례에서 필요한 기능·주체·제약·증거·미확인 항목을 서로 연결해 설명할 수 있는 것이다. 지금 참고 반영 단계에서 실제 위험등급·PLr·달성 PL·합격 수치나 인증 효력을 부여하지 않는다. 원래 코드 구축은 설계 이후에 진행한다는 순서는 유지한다.
