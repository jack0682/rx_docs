## Structural rules to publish

1. Validate complete unframed protobuf message bytes before typed decoding and validate generated bytes before transport encoding. gRPC framing and authentication remain separate.
2. Whole message length <=1048576 bytes; larger input RESOURCE_EXHAUSTED.
3. A root starts at depth0. Entering a message at depth64 is INVALID_ARGUMENT. Thus at most64 message levels including root, not64 child levels.
4. Shared work budget65536 across all nested messages: each field occurrence costs1, and each scalar inside a packed segment costs another1. Multiple packed segments each cost their own field occurrence. Budget exhaustion RESOURCE_EXHAUSTED. This is not just a count of field tags.
5. Varints must terminate in <=10 bytes, tenth byte <=1. Truncation/overflow rejected. Minimal/shortest encoding is NOT required by the current scanner; no canonical protobuf byte-string promise.
6. Field tag0 and field-number conversion overflow rejected. Unknown descriptor fields rejected; no preservation. Descriptor field numbers already constrain legal schemas.
7. Any encoded map occurrence rejected. Frozen published schemas contain no maps. An absent map field is not inspected, so do not claim the current scanner rejects a schema merely for declaring a map.
8. Singular field occurrence at most1, including singular messages and proto3 optional fields. Repeated fields may recur.
9. Oneof arms at most1 occurrence total. Every nonsynthetic oneof in an encountered message must have an arm. Synthetic optional oneofs may be absent.
10. Scalar kinds use protobuf wire types 0/1/2/5. Wrong wire kind rejected. Packable repeated scalar fields accept packed and unpacked encodings and multiple packed segments; packed contents obey scalar validation and shared budget.
11. Encoded bool only0/1. Encoded uint32/sint32 varint must fit unsigned32 before zigzag conversion. Int64/sint64 use bounded64-bit varint; fixed values use little endian. Avoid inventing extra int32 canonicality or width rules not exercised by the published schema.
12. Every encoded enum occurrence must be a known positive enum value <=INT32_MAX; explicit0 rejected. Omission of an ordinary proto3 enum produces default0 after parsing and is NOT rejected at the wire layer. Business/model validation must still reject unsupported defaults where required.
13. Encoded float/double must be finite, packed or unpacked. Exact fixed widths and all length-delimited boundaries are checked.
14. Encoded strings must be well-formed UTF-8; bytes fields are arbitrary bytes. Length varint overflow/truncation rejected.
15. Apart from nonsynthetic oneofs, the scanner does not require ordinary fields/submessages to occur. Missing ID/digest/context, semantic alias formats, authentication, readiness, work permission, resource ownership and completion are separate checks.
16. Native typed parser remains the last parse step; codec success is not business admission. Error category must be shared across language TCK, while diagnostic text need not be identical unless explicitly specified.

## Existing schema coverage versus synthetic guard probes

Use independently authored literal byte vectors, and declarative repeat/nest recipes
for boundary-sized inputs, with expected acceptance/status written from these rules.
No vectors or expectations are emitted by invoking Rust/Python/C++ codecs.
Depth64, maps and some scalar kinds may require an explicitly TCK-only descriptor
because the frozen public schemas do not contain arbitrary recursion/maps/all kinds.
Keep those guard probes distinct from actual public-message StrictCodec encode/decode.
A retained private-source mutation must make a fixed expected vector fail, not regenerate it.

## Material plan corrections observed before implementation

- Standard protobuf encoding is not categorically incompatible. Existing wire.rs explicitly round-trips prost-generated messages under strict::decode. The issue is missing published profile and additional rejected protobuf representations.
- OperationService.Submit and Lookup in rx-api/src/grpc/operation.rs return UNIMPLEMENTED deliberately. Submit says use mandatory cell admission; Lookup says recover Cell.SubmitOperation by same cell request. Wiring a new base Submit around cell checks would weaken the boundary.
- The real resident rx-platformd does serve PlatformIngress (src/lib.rs347,408). The grpc README's old composition-only opening is stale; runtime absence must not be inferred from it.
- G3/G4 RegisteredSupervisor work-use gates have no gRPC ingress. Their external signed-decision DTOs are a different contract from platform cell Operation RPCs. Existing no-bypass regressions alone cannot truthfully be called SDK-mediated work-use positive/negative tests.
- The addendum asks a first ROBOTIS connection using a real runtime, allowing a simulated device/observation, not just dependency research. Clarify which bounded connection belongs here without silently turning the whole five-product bundle into done.
- The prior scratch SDK-PLAN.md and surveys remain unmodified; their claim that Operation.Submit/Lookup is implemented is contradicted by current source.
