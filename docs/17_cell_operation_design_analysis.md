# 다음 설계 분석 — 셀의 운전 조건·허가·개입·복구

> 후속 확정 결과: [셀 운영 계약 v1.0](18_cell_operations_contract.md). 이 문서는 그 설계를 위한 선행 입력/분석으로 보존한다.

2026-09-10 · 상태: 후속 설계 분석과 개념 제안. 실제 운전 절차·안전기능·프로토콜 개정 확정본이 아니다.

## 1. 다음에 설계할 것과 이유

**다음 설계 단위는 ‘셀 운영 계약’이다.** 첫 레이저 셀에서 어떤 작업을 허용하는지, 조건이 바뀌면 무엇을 제한하는지, 작업자가 개입한 뒤 무엇을 확인해야 다시 시작할 수 있는지를 정의한다. 이 과정에서 필요한 안전기능과 제작팀·장비 공급사·설치팀의 책임을 함께 도출한다.

[계약 v1.0](contracts/v1.0/README.md)은 한 작업의 접수·전달·결과·불명·복구를 설명한다. [16 안전 자료 연결](16_safety_requirements_contract_link.md)은 그 작업을 허용할 사용 조건과 검증 근거가 필요함을 정리했다. 이제 둘을 실제 셀의 운전·개입 사례에 적용해야 한다.

| 다음 작업 후보 | 지금 얻는 것 | 아직 해결하지 못하는 것 | 판단 |
|---|---|---|---|
| RPC·필드 추가 | 데이터 표현 상세화 | 무엇을 확인해야 작업을 허용하는지 | 운영 의미를 정한 뒤 필요한 변경만 도출 |
| 첫 BT 트리 작성 | 정상 순서와 분기 가시화 | 미확정 ‘빼기’, 소재 지지, 사람 개입, 재시작 조건 | 실제 순서 확인과 운영 계약을 선행 |
| 모든 모델의 안전 표준·기능 전부 상세화 | 장기 검토 범위 확대 | 첫 셀에 적용할 구체 조건이 없으면 추상 문서 증가 | 공통 틀은 마련하고 첫 사례로 구체화 |
| **셀 운영 조건·허가·개입·복구 모델** | 실제 작업·장비·사람·위험·근거를 같은 사례에 연결 | 최종 신호·시간·성능은 공급사·현장 확인 필요 | **우선 진행** |

이 우선순위는 RX의 현재 입력과 사업 목적에 따른 설계 판단이다. 언어·레포 수·기존 공통 프로토콜을 다시 선택하는 단계는 아니다.

## 2. 확정된 입력과 빈칸

| 항목 | 현재 입력 | 설계에서의 처리 |
|---|---|---|
| 첫 공정 | 레이저 열처리 설비의 소재 공급 | 가공 전체 제어를 RX의 확정 책임으로 추가하지 않음 |
| 언급된 작업 | 소재 집기, 지그/척 관련 작업, 문 닫기, 다음 소재 준비 | 실행 가능한 순서가 아니라 작업 후보 집합으로 사용 |
| ‘빼기’ | 로봇 후퇴인지 소재 회수인지 미확정 | 서로 다른 작업 카드로 구별하고 현장 확인 전 합치지 않음 |
| 설비 PLC | Mitsubishi Q03UDVCPU 및 CC-Link 자료 | 통신 접점과 안전기능 할당이 확인됐다는 뜻은 아님 |
| 레이저 제어부 | 모델·설비 PLC와의 관계·방호 조건 미확정 | 레이저 작동/진입 허용의 공급사 책임과 근거 확인 필요 |
| 첫 로봇 | OMY·UR5e·FR3 후보 | 특정 모델을 선정한 것으로 가정하지 않고 공통 사례 작성 |
| 사람 개입 | 필요하지만 위치·이유·권한·복귀 조건 미확정 | 정상 자동 작업과 개입 절차를 별도 모델로 다룸 |
| 사업 목적 | 인건비 절감 | 정상 사이클마다 불필요한 확인 조작을 넣지 않고 남는 작업·복구 부담을 측정 |

장비·공정 사실의 입력은 [제품 범위](03_product_scope.md), [첫 셀 초안](11_first_cell_contract.md), [레이저 PLC 기록](../references/laser_plc_interface.md)이다. 부족한 정보 때문에 일반 구조 설계까지 멈출 필요는 없지만, 그 정보를 요구하는 특정 실행 조건을 참으로 처리할 수는 없다.

## 3. ‘허가’를 네 가지로 구별한다

| 구분 | 답하는 질문 | 유효 범위·갱신 |
|---|---|---|
| **검증한 사용 범위** | 어떤 장비·공구·소재·하중·자세·환경·공정 조합을 확인했는가? | 시험·평가 대상 구성에 결합. 관련 변경/철회 시 재검토 |
| **현재 작업 시작 조건** | 지금 이 작업에 필요한 관측·자원·제어권·미결 상태가 적합한가? | 작업별·현재 시점 조건. 오래된 판단을 재사용하지 않음 |
| **시작 의도** | 누가 어떤 운전/작업을 의도적으로 시작했는가? | 승인된 자동 run의 범위와 별도 개입 후 재시작을 구별 |
| **현장의 보호 기능** | 위험을 실제로 감지·억제·정지·지지하는 기능이 유효한가? | 해당 기능이 요구하는 실행 경로·시간·고장 대응으로 유지 |

앞의 세 가지는 RX가 관리할 운영 판단이다. 마지막 기능을 RX의 일반 DB 승인이나 `ready=true`로 대체하지 않는다. 안전 관련 제어부에는 소프트웨어를 포함한 별도의 설계·통합 요구가 연결된다. [ISO 13849-1:2023 공개 범위](https://www.iso.org/standard/73481.html)

설계용 논리식은 다음과 같다.

> RX의 새 일반 작업 전달 검토 통과 = 검증 범위 일치 ∧ 현재 조건 충족 ∧ 유효한 제어권 ∧ 상충하는 미결 작업 없음 ∧ 유효한 시작 의도

이 식은 RX의 운영 판단 범위다. 실제 기동에는 전달 직전 장비 조건과 할당된 현장 보호 기능의 조건도 충족돼야 한다. RX의 판단 결과를 그 조건들이 충족됐다는 충분조건으로 사용하지 않는다.

각 조건은 **충족·불충족·미확인**을 구별한다. 필요한 조건이 불충족/미확인이면 그 조건에 의존하는 새 일반 작업을 허용하지 않는다. 영향을 받는 범위를 판단할 수 없으면 첫 셀의 새 생산 시작을 보류한다. 보호 반응·정지/지지·조회·승인된 복구는 일반 생산과 별도 정책을 적용하며, DB에 기록할 수 없다는 이유로 필요한 현지 보호 반응을 막지 않는다.

`허용`은 검사 시점에 관한 판단이다. Host의 전달 직전 재검사와 운전 중 필요한 현장 보호 기능이 이어져야 한다. ‘허용 기록을 durable 저장했으므로 계속 움직여도 됨’이라는 의미를 부여하지 않는다.

## 4. 최소로 필요한 운영 객체

새 공통 코어 모듈이나 protobuf 이름을 먼저 고정하지 않는다. 아래는 소유자·연결·유효성의 개념 모델이다.

| 객체 | 최소 내용 | 소유·판정 역할 |
|---|---|---|
| 사용 범위 | 장비/공정/tool/지그/소재/환경/허용 모드와 각 revision | 통합 엔지니어 작성, 제작팀·OEM의 사용 한계와 대조 |
| 위험·기능 연결 | 위험 ID→필요한 조치/안전기능→구현 주체→검증자료→잔존 위험 | 설치팀이 셀 전체를 통합; 공급사는 제품 기능 근거 제공 |
| 조건 정의 | 어떤 작업에 필요한지, 원본 신호/자료, 판정 방식, freshness, 상실 시 영향 | solutions의 현장/장비 명세, platform의 공통 판정 규칙 |
| 허용 판단 기록 | 대상 작업/범위, 구성 revision, 제어권/개입 세대, 사용 근거, 판정 사유 | platform. native 동작을 직접 수행하는 권한 증서로 오인하지 않음 |
| 개입 사례 | 원인, 영향 자원·소재, 진행 중 작업, 현장 절차, 담당자, 재확인·처분·재시작 기록 | 현장 담당자의 행위와 platform 기록을 연결 |
| 변경 영향 | 변경 전후 revision, 의존 관계, 재검토할 평가/시험/사용 범위 | 엔지니어·검증·릴리스 담당 |

구성 revision은 tool·교정·공정 변경을, 개입/운용 세대는 같은 구성에서도 수동 조작·정지·재시작으로 이전 판단이 유효하지 않게 되는 변화를 표현한다. 세대 값을 올리는 것만으로 물리 상태가 확인되는 것은 아니다.

**소재 지지는 자원 lock과 구분한다.** controller를 RX가 소유하고 있어도 실제 소재는 떨어졌을 수 있다. 인계 중에는 그리퍼와 척이 동시에 지지할 수도 있으므로 지지 주체를 항상 하나로 강제하지 않는다. 실제 지지/착좌/고정의 주장, 관측 근거와 미확인을 표현하고, 특정 인계 단계에 필요한 조건은 공정·기구 명세가 정해야 한다. 범용 gripper 완료 bit 하나로 모두 표현하지 않는다.

## 5. 첫 레이저 셀에 대입할 작업 카드

다음 행은 설계를 위한 의존 조건이다. 실제 로봇 동작·문 개방·척 해제 순서를 지시하지 않는다.

| 작업 후보 | 먼저 정의해야 할 조건 | 완료만으로 추론하면 안 되는 것 |
|---|---|---|
| 소재 집기 | 품목/tool 일치, 접근 범위, 파지 방법·관측·물체 지지 조건 | gripper motor 도달=소재 파지 |
| 지그에 소재 공급 | 로봇/설비 좌표·착좌 허용범위, 설비 진입 조건 | trajectory 성공=정상 착좌 |
| 척 고정 | 실제 소재·지그 조합, 고정 상태의 신호 의미, 인계 조건 | PLC 쓰기 성공=필요 고정력 확보 |
| 그리퍼 해제 | 해당 단계의 지지/고정 확인과 실패 대응 | 척 닫힘 bit 하나가 모든 낙하 위험을 해소 |
| 로봇 후퇴 | 공구·소재·팔의 이탈 판정 범위 | 목표 joint 위치 도달=모든 부위 이탈 |
| 문 닫기 | 문 사이 공간·접근·로봇 상태, 문 자체 위험과 제어 주체 | 문 닫힘=잠금=레이저 작동 허가 |
| 다음 소재 준비 | 공유 controller·작업 영역·보관 위치, 병행 가능 범위 | 다른 논리 작업이므로 자동 병렬 가능 |
| 가공 연동 | 시작 책임, 실제 가공부 상태, 방호/진입/완료 의미 | 소재 공급 범위에 가공 start 책임이 이미 포함됨 |

로봇 표준만으로 레이저 가공 위험을 다루지는 않는다. ISO 11553-1:2020은 재료를 레이저로 가공하는 기계의 레이저 방사 위험을 다루고, IEC 60825-1은 레이저 제품의 분류·요구를 다룬다. 첫 셀의 OEM 문서와 함께 **적용성을 대조할 후보**로 추가한다. 이 공개 범위 확인으로 해당 설비의 등급·허용 노출·방호 구조나 인증을 판정하지 않는다. [ISO 11553-1:2020](https://www.iso.org/standard/67658.html), [IEC 60825-1:2014](https://webstore.iec.ch/en/publication/3587)

## 6. 첫 개입·복구 사례의 분석

**SR01: 소재 공급 도중 결과가 불명이고 작업자가 개입해야 하는 경우**를 첫 상세 사례로 권한다. 한 사례 안에 상태·제어권·물리 지지·사람 접근·재시작·생산 기록이 모두 나타나기 때문이다.

| 단계 | 확인·기록할 것 | 다음 단계의 조건 |
|---|---|---|
| 이상 인지 | 어떤 요청의 결과를 모르는지, 마지막 유효 관측·소재·장비 상태 | 관련 새 생산 작업 제한. 물리 정지는 별도 확인 |
| 현지 반응 | 필요한 정지/지지/위험 억제 기능과 실제 반응 | 제어기·센서·현장 절차가 제공하는 근거 |
| 개입 준비 | 누가 어디에 어떤 목적으로 접근하는지, 접근·정비 절차의 조건 | 검증된 현장 절차에 따른 접근 허용. RX 알림 확인만으로 접근 허용 생성 금지 |
| 개입 기록 | 실제 수동 조작, 소재 이동·교체, tool/교정 변화 | 기존 위치·지지·완료 가정 중 무효화된 항목 식별 |
| 재확인 | 인원/구역, 물리 상태, 잔류 명령, 모드·owner·변경 영향 | 해당 사용 범위와 현재 조건이 다시 충족됨 |
| 처분과 재시작 | 이전 불명 작업의 조사/포기 처분, 재개 지점, 새로운 시작 의도 | 명시된 절차로만 새 run/activation 허용 |

불명 작업을 ‘사람이 확인했으므로 성공’으로 덮어쓰지 않는다. 사람이 확인할 수 있는 현재 사실과 확인할 수 없는 과거 결과를 구별한다. 과거 결과는 UNRESOLVED로 남겨도 현재 상태·잔류 명령·인계 조건을 확보한 뒤 새 작업을 시작할 수 있도록 설계한다. 이는 v1.0의 RecoveryDisposition과 연결된다.

리셋·모드 선택·재시작은 독립 행위다. 다만 정상적인 자동 운전의 매 단계마다 새 사람 승인을 요구한다는 뜻은 아니다. 승인된 recipe/run의 시작 의도가 허용한 범위에서는 Runtime이 작업별 조건을 검사하며 연속 실행한다. 보호 기능 작동 후 재시작·사람 개입·운전권 전환·검증 범위를 벗어난 변경은 별도 사건으로 취급한다. 상세 자동/수동 재시작 조건은 적용 기능·현장 위험성평가로 정한다. 예기치 않은 기동 검토에는 전기 외에 유공압·중력·저장 에너지도 포함된다. [ISO 14118:2017](https://www.iso.org/standard/66460.html)

## 7. 안전기능 명세에서 결정할 질문

아래 후보는 특정 제어기에 이미 존재하는 기능이 아니다. 위험성평가로 필요 여부와 범위를 정하고 기능별 명세로 분해한다.

| 기능 후보 | 반드시 결정할 것 | 공급사/제작팀 입력 |
|---|---|---|
| 설비 진입·가공 억제 | 무엇을 진입으로 보고 어떤 위험동작을 제한하는가? | 레이저/OEM의 모드·방호·진입 가능 상태·신호 및 반응 |
| 소재 유지·인계 실패 대응 | 무엇이 지지하고 어떤 고장에서도 어느 상태를 유지해야 하는가? | gripper/척/지그의 구조·감지·압력/전원 상실 거동 |
| 통신·제어권 상실 대응 | 어떤 연결 상실에 어떤 장비가 어떻게 반응하는가? | 현지 감시·정지/지지 기능, 시간·고장·종료 조건 |
| 예기치 않은 재기동 방지 | reset·mode 선택·run 시작·잔류 명령을 어떻게 구별하는가? | 실제 controller/PLC 기동 의미·세션/queue 처리 |
| 이동·전신 안정성 | 작업 중 위치/지지·정지 과정·에너지 부족에 어떻게 대응하는가? | 바퀴형 도킹/제동, 족형 반력/지지/회복 동작의 검증된 한계 |

각 명세에는 `위험/사용조건 → trigger → 센서/판단/통신/출력/구동의 책임 → 요구 상태와 유지 조건 → 반응 시간과 요구 성능의 근거 → 고장 대응 → reset/start → 시험조건/판정근거`를 적는다. 실제 PLr·달성 PL/SIL·반응시간은 현재 자료만으로 수치를 채우지 않는다. ISO 12100은 위험성평가·위험 감소의 기본 원칙이며, 제어부에 할당한 기능의 설계는 적용 기능안전 체계와 연결해야 한다. [ISO 12100:2010](https://www.iso.org/standard/51528.html), [ISO 13849-1:2023](https://www.iso.org/standard/73481.html)

## 8. 소프트웨어 배치와 기존 계약 영향

| 위치 | 다음 설계에서 맡길 책임 | 맡겼다고 주장하지 않을 것 |
|---|---|---|
| rx-platform | 공통 조건 판정, 사용 범위/구성 참조, 사유·무효화·개입·복구·판단 이력 | 안전 관련 제어의 검증 없이 위험 감소 성능을 보장 |
| rx-solutions | 장비별 신호 의미·native mode/정지/지지 연결, 공정별 조건, 현장 UI/절차, 기본 자사 플랫폼 profile | package 포함만으로 모든 모델의 현장 허용 완료 |
| 실제 장비·안전 관련 제어 경로 | 할당된 감지·억제·정지·지지·고장 대응을 필요한 조건에서 실행 | ‘장비 측에 있다’는 위치만으로 기능안전 달성 |

이들은 책임 경계다. 별도 ‘안전 코어’나 세 번째 레포/컨테이너를 추가한다는 결정이 아니다. 일반 RX와 안전 관련 제어 경로의 간섭·공통 원인 고장·자원 경합도 기능 할당 시 검토한다.

기존 v1.0의 operation/evidence/profile digest/제어권/복구 규칙은 재사용한다. 먼저 profile·현장 자료·UI 수준으로 표현 가능한지 분석한다. 새로운 자료 schema를 쓴다면 그 schema의 지원 버전·검증을 명시하고, digest만 같으면 내용을 이해했다고 가정하지 않는다. 새 공통 wire message가 필요한 항목만 후속 revision의 변경 후보로 정한다. 현재 v1.0 규범 파일과 manifest는 변경하지 않는다.

## 9. 설계를 검토할 반례

| 반례 | 설계가 설명해야 할 결과 |
|---|---|
| 시작 직전 tool/교정/공정 revision이 바뀜 | 이전 판단을 재사용하지 않으며 아직 전달하지 않은 작업을 새 조건으로 검토 |
| READY 표시 뒤 사람이 수동으로 소재/로봇을 이동 | UI 캐시와 별개로 이전 관측/시작 의도/개입 세대의 유효성 검토 |
| 현재 조건 상실 때 native 명령이 이미 실행 중 | 새 명령 차단과 현지 보호 반응을 구별. revoke가 과거 물리 효과를 취소했다고 하지 않음 |
| reset과 start가 같은 버튼/호출에 묶임 | 둘의 의미·권한·실제 부작용을 검토하고 허용 조건을 분리 |
| 작업자 확인 없이 자동 단계만 반복 | 승인된 run 범위 안의 정상 자동 실행인지 검사. 매 회 사람 클릭을 자동 요구하지 않음 |
| 지그만 바꿨는데 동일 품번이라 기존 검증을 사용 | 변경 의존 관계로 영향을 받는 인계·좌표·위험·시험을 재검토 |
| 안전 상태의 표시용 사본은 GOOD지만 실제 기능이 해제됨 | 데이터 품질과 보호 기능의 유효성을 구별하고 관측·검증 범위의 한계를 드러냄 |
| 정지 명령 뒤 gripper나 몸체 지지가 사라짐 | 정지·지지·에너지 조건을 개별 기능 및 결합 상태로 평가 |

## 10. 구체화 순서와 산출물

| 순서 | 다음 명세 | 지금 작성 가능한 것 | 종료 조건 |
|---|---|---|---|
| N01 | 첫 셀 사용 조건·업무/장비 경계 | §2·5를 바탕으로 작업/사람/설비 범위와 정보 빈칸 | 모델·작업·개입의 가정과 확인사항이 분리됨 |
| N02 | SR01 개입·복구 사례 카드 | §6의 사건별 주체·지식·조치·근거·허용 범위 | 정상/유실/수동 변경/재시작의 분기를 설명 가능 |
| N03 | 위험과 기능 할당 명세 | 실제 위험 행과 §7의 기능 후보·책임·자료 요구 | 위험마다 구현 주체·필요 근거·미확정 수치의 출처가 연결됨 |
| N04 | 운영 조건·허가·무효화 명세 | §3·4의 판정과 유효 범위, 동시 변경·개입 경합 | 허용/보류/철회의 원인과 범위가 일관됨 |
| N05 | 현장 UI·binding·변경 영향 | 필요한 신호, 작업자 행위, revision/증빙 연결 | 운영자가 왜 시작 불가인지와 다음 조치를 이해 가능 |
| N06 | 설계 검토 및 v1.0 변경 영향 | §9 반례와 기존 SC/V 항목의 연결 | 재사용/현장 설정/공통 schema 변경을 구별하고 후속 시험을 명시 |

N01–N04는 한 번에 완벽히 끝내는 직렬 단계가 아니다. SR01 한 사례로 운영 의미와 기능 할당을 왕복하며 구체화한다. 첫 문서에는 확인되지 않은 값이 남을 수 있지만, 어떤 동작을 막는 값인지와 확보 책임/자료를 분명히 해야 한다.

| 우선 필요한 실제 정보 | 확보할 역할 | 영향을 받는 설계 |
|---|---|---|
| 첫 로봇/그리퍼/지그와 소재 인계 방식 | 기구·로봇 제작/통합 | 사용 범위·인계 근거·정지/지지 |
| 실제 작업 순서와 ‘빼기’ 의미 | 현장 공정 담당 | 정상 흐름·개입 지점·병행 |
| 문/척/레이저 상태 및 자동화 연결 조건 | 설비 OEM·PLC 담당 | 진입·가공 억제·관측·기능 할당 |
| 작업자 개입 위치·작업·복귀 절차 | 현장 운영·설치 | SR01·접근/재시작·UI |
| 실제 안전기능과 시험 범위 | 제작팀·OEM·검증 담당 | 요구 성능·검증 자료·납품 허용 |

이 표는 설계 입력 backlog다. 아직 없는 답변이나 자료를 이미 확인한 것으로 기록하지 않는다.

## 11. 사업적으로 이 단계가 필요한 이유

인건비 절감은 로봇이 움직인 시간보다 자동화 후에도 남는 준비·보충·감시·개입·복구 업무에 영향을 받는다. 그래서 운영 설계는 안전 조건을 충족하면서 정상 자동 실행을 반복할 범위와 사람이 맡을 예외를 명확하게 해야 한다. 작업자 개입을 막연하게 남겨두면 납품 후 필요한 인원과 지원 공수를 예측하기 어렵다.

이 단계의 재사용 자산은 공통 허가·무효화·개입 기록 방식, 장비별 기능/근거 연결, 검증된 복구 사례다. 모든 고객의 물리 정지 방법을 하나로 통일하는 것은 재사용 목표가 아니다. 납품 때는 **어떤 품목·구성·운영 조건에서 어느 자동 범위와 어떤 개입·지원 범위를 제공하는지**를 인수 기준에 연결한다. 금액·인원 절감·ROI·검증된 성공률은 현재 산출하지 않는다. [사업 가치 기준](02_value_and_business.md)

## 12. 분석 결과와 범위

이번 분석에서는 다음 설계의 우선순위를 셀 운영 계약으로 정하고, 네 종류의 허가/조건, 여섯 운영 객체, 첫 작업 카드, SR01 사건표, 기능 할당 질문, 반례, N01–N06의 산출물을 제안했다. 새 프로토콜 번호·위험등급·안전기능 성능·실물 운전 절차를 확정하지 않았다.

표준 출처는 2026-09-10 공식 공개 설명을 확인한 범위다. 표준 전문의 조항별 적합성, 실제 설비 분류와 법적/계약상 책임은 이 분석만으로 확정하지 않는다. 후속 작업은 **N01 첫 셀 경계와 N02 SR01 개입·복구 카드**부터 구체화하는 것이 적절하다.
