## 1. RX의 정의

**RX는 서로 다른 로봇과 생산설비의 기능을 공통 작업 계약으로 연결하고, 현장 공정을 구성·검증·실행·운영·유지보수하는 산업자동화 소프트웨어 제품이다.**

회사는 RX를 기반으로 고객 현장의 자동화 과제를 해결한다. 로봇을 선정하고 어디에 배치할지, 어떤 지그와 그리퍼를 사용할지, 공정을 어떤 순서로 수행할지 설계한다. 그 결과를 장비·소프트웨어·설치·지원이 결합된 솔루션으로 납품한다.

이 정의에서 가장 중요한 제공 단위는 ‘고객이 반복 운영할 수 있는 자동화 작업’이다. SDK나 실행 코어는 이를 만드는 내부 자산이고, 현장에 필요한 앱·설정·절차·검증과 함께 제품을 이룬다.

소프트웨어 제품의 두 축은 공통 미들웨어 프레임워크와 현장 애플리케이션이다. 프레임워크는 장비 작업·실행·확장 규칙을 제공하고, 애플리케이션은 이를 구성·운영·진단하는 사용자 경험을 제공한다. 둘을 같은 작업·버전·기록으로 연결한다.

## 2. 사업·상품·소프트웨어의 관계

| 용어 | 이 문서의 정의 | 예 |
|---|---|---|
| RX 사업 | 고객의 자동화 문제를 해결하고 납품·지원에서 수익을 만드는 활동 | 소재 공급 자동화 구축과 유지보수 |
| 납품 솔루션 | 특정 현장·품목·운영 조건에 맞춰 제공하는 전체 구성 | 로봇, 지그·그리퍼, 설비 연동, 앱, 교육·인수 |
| RX 소프트웨어 제품 | 여러 납품에서 재사용하며 버전·품질·지원 범위를 관리하는 소프트웨어 | 구성·운영 앱, Runtime, 어댑터 SDK, 진단·배포 도구 |
| 현장 패키지 | 공통 제품을 실제 기계와 공정에 적용하는 버전 있는 자산 | 장비 프로파일, 공정, 좌표, 복구 절차, 검증 기록 |
| 코어 라이브러리 | 장비 종류에 관계없이 지켜야 할 실행 의미를 구현한 내부 구성요소 | 작업 식별·상태·판정·중복·복구 규칙 |

첫 단계에서는 솔루션 납품에 소프트웨어 사용·지원을 포함하는 모델을 검토한다. 프레임워크 단독 판매, 파트너 라이선스, 구독 등의 상품화는 고객과 지원 비용을 확인한 뒤 결정한다. 이 문서는 과금 모델을 확정하지 않는다.

## 3. 어떤 수준의 공통 계층을 만드는가

RX는 ‘문을 닫는다’, ‘정의된 로봇 동작을 수행한다’, ‘가공 완료를 확인한다’와 같은 장비 작업의 의미를 공정에 제공한다. 그 아래의 ROS action, 제조사 SDK, PLC register, fieldbus 신호는 연동 모듈과 기계 프로파일이 처리한다.

RX가 모든 장비의 모든 기능을 동일하게 만드는 것은 불가능하다. 어떤 장비는 완료 결과를 직접 제공하고, 어떤 장비는 센서 후조건이나 작업자 확인이 필요하다. 공통 계층은 이 차이를 표현하고 그 수준에 맞게 실행·복구 범위를 제한해야 한다.

제품 구조상 사용하는 명칭은 기능을 설명하기 위한 작업명이다. 구성 도구·운영 앱·Runtime 등을 각각 별도 상표나 별도 판매 제품으로 확정한 것은 아니다.

## 4. 왜 공통 프레임워크가 필요한가

장비를 추가할 때 매번 요청 중복, 상태 표시, 오류 기록, 재시작 처리를 새로 만들면 같은 운영 문제가 여러 구현에 흩어진다. 공통 규칙을 공유하면 수정·시험·교육을 재사용할 수 있고, 현장별 차이를 어디에서 처리했는지 추적하기 쉽다.

이것은 사업 가설이기도 하다. 공통화 비용보다 반복 납품에서 절약되는 비용이 커야 한다. 첫 셀에서는 필요한 만큼만 공통화하고, 두 번째 장비·현장에서 실제 변경량과 검증 비용을 측정해 경계를 조정한다.

제품성을 판단하는 기준은 다음과 같다.

- 지원하는 조합과 운영 범위를 명시할 수 있다.
- 다른 담당자가 설치·운영·진단할 수 있다.
- 같은 결함의 수정과 검증을 여러 현장에 적용할 수 있다.
- 현장 변경이 어떤 코드·설정·검증에 영향을 주는지 설명할 수 있다.
- 정상 운전뿐 아니라 실패·결과 불명·개입·복구까지 납품 범위에 포함한다.

코어의 코드량이나 플러그인 개수만으로 이 기준을 충족하지는 않는다.

## 5. 재사용 자산을 나누는 단위

| 자산 | 담는 것 | 재사용의 조건 |
|---|---|---|
| 공통 실행 규칙 | 식별·상태·결과·기록·복구의 의미 | 계약이 같고 요구 보장이 유지됨 |
| 통신 어댑터 | 제조사 SDK·프로토콜 호출과 오류·상태 수집 | 지원 SDK·OS·제어기 범위가 맞음 |
| 기계 프로파일 | 신호 의미·모드·완료 판정·장비 옵션 | 실제 기계와 배선·프로그램이 맞음 |
| 작업·공정 템플릿 | 반복되는 작업의 구조·분기·입력 | 현장 파라미터와 시작·완료 조건 검증 |
| 현장 패키지 | 기계·품목·tool·교정·공정의 정확한 조합 | 해당 현장·버전에서 인수된 범위 |
| 시험·지원 자산 | 모의 장비, 계약 시험, 진단·복구 안내 | 변경 영향에 따라 재검증 |

로봇 교체 시에는 어댑터 외에도 도달 범위, 그리퍼, tool·좌표, 경로, 공정 시간과 검증이 바뀔 수 있다. 목표는 필요한 변경을 명확히 제한하고 공통 실행 규칙을 재사용하는 것이다.

## 6. 제품이 성장하는 방향

첫 셀의 소재 공급을 실제 운영 가능한 범위로 완성한다. 이어서 다른 품목·로봇·설비에 적용하며 연결 계약과 공정 자산의 재사용을 검증한다. 그 위에 작업지시·실적·정지 사유·여러 셀의 운영 관리 기능을 확대한다.

자사 AI Worker·AI Sapiens를 포함한 기본 제어·연결·설정·진단 지원은 필수 통합 범위다. 이동·도킹·배터리·공유 공간 등을 결합한 새로운 현장 공정은 추가 작업·자원 계약과 검증이 필요할 수 있다. 기존 자사 제어 스택을 활용하면서 공정 확장 범위를 실제 사용 사례로 구체화한다. 최신 필수 의존성과 레포 경계는 [스택·컨테이너 제안](12_stack_and_container_proposal.md)을 따른다.
